# Contrato clínico M6.4 — gamebras.clinical/1

A campanha JSON contém `clinicalModule`. `cases` declara ID, narrativa, estado inicial; `patients` associa nomes dos NPCs aos casos; `actions` define duração, recurso opcional e grupos de regras. Cada grupo contém `rules` e `flow`: o executor M6.3 recebe os booleanos `matchN` calculados das condições, e as ações `chooseN` selecionam uma regra. A primeira condição verdadeira vence no fluxo padrão. Os efeitos só alteram campos de estado já declarados. `when`, `set`, `observe` e `message` aceitam literais ou arrays de expressão (`get`, `and`, `or`, `not`, `eq`, `ne`, `lt`, `lte`, `gte`, `add`, `sub`, `mul`, `min`, `max`, `round`, `concat`). Sem JavaScript de módulo. `evolution` contém expressões simultâneas por minuto; `behavior`, `triage`, `guidance`, `exam` são grupos de regras com `value`. `observations` define rótulos e unidades. `classification` distingue indicação e erro; `points` separa pontuação; `outcome` encerra atendimento. `profiles`, `facilitator`, `references`, `docs`, `glossary` e `completionFlag` são dados da campanha. A engine não contém critérios de diabetes.

O JSON isolado desta pasta pode ser importado com os assets e documentos no mesmo ZIP. O bundle principal mantém as outras campanhas. Este snapshot é experimental, não instrumento de decisão clínica. O editor de fluxograma mostra o fluxo efetivamente usado, mas suas edições ainda são prévias. O modelo de fisiologia é simplificado, não validado clinicamente. A revisão dos sprites exclusivos e uma segunda campanha espacial completa permanecem pendentes. A geração de novos HTMLs no navegador ainda necessita selagem de identidade atualizada (M6.1 via ferramenta local); não confundir exportação com versão verificada. Use os testes e o manifesto para continuidade.
